## Найденные причины

Для каждой проблемы: воспроизведение → причина → исправление → проверка.

1. При быстром переключении иногда открываются данные предыдущей заявки.
- Пооткрывал карточки
- При выборе сбойной карточки (без источника) предсказуемо не загружается контент - остается контент предыдущей карточки.
- Исправление в пункте 2 (причина на оба пункта одна). Добавил проверку на "!error" на фронте.
- Проверил - теперь загружается текст ошибки, но не контент.

2. Карточка заявки без источника загружается с ошибкой.
- Проверил вкладку Network в браузере. Увидел там текст ошибки из [bootstrap.php:12](backend/src/bootstrap.php#L12).
- Серверные логи указывали на `TicketRepository::find`
- При изучении метода стало понятно, что нет проверки на `false` для `$source`. Добавил проверку.
- Карточки открываются, сервер возвращает корректный ответ

3. Сотрудник с правом только на просмотр смог изменить источник.
- Отправил проверочный запрос от "Просмотр" через Postman:
```shell
curl --location 'http://localhost:5173/api/tickets/102/source' \
--header 'x-csrf-token: ***' \
--header 'Content-Type: application/json' \
--header 'Cookie: assessment_session=***' \
--data '{
    "source_id": 2
}'
```
- Нашел `TicketRepository::changeSource` - нет проверки прав на стороне сервера.
- Бегло просмотрел код фронтенда - нашел проверку "role=editor". Оно же есть в тестовых данных БД. Добавил проверку на стороне сервера.
- Повторил проверку в Postman - получил 403.
